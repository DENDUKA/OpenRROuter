# BILLING-004: Polly Retry + Circuit Breaker для Usage Events

**Цель:** Обеспечить надёжную доставку usage events из ApiGateway в BillingService через retry с exponential backoff и circuit breaker. Решает 99% transient failures (сеть, кратковременный даун BillingService).

**Архитектура:** Добавляем `Microsoft.Extensions.Http.Resilience` (обёртка над Polly 8.x) на gRPC-клиент BillingService. Retry 3 раза с exponential backoff + circuit breaker. Существующий fire-and-forget паттерн в `ChatCompletionHandler` не меняется.

## Задача 2: Добавить resilience pipeline на gRPC-клиент Billing

**Файл:** `src/OpenRussiaRouter.ApiGateway/Application/Extensions/ApiGatewayExtensions.cs`

Добавить `using` в начало файла:

```csharp
using Microsoft.Extensions.Http.Resilience;
using Polly;
```

Затем добавить `.AddResilienceHandler(...)` в цепочку регистрации billing gRPC-клиента (строки 72-87):

```csharp
// Существующий код (строки 72-87):
var billingGrpcUrl = configuration["GrpcServices:Billing"] ?? "http://localhost:5002";
services.AddGrpcClient<BillingGrpc.BillingServiceClient>(options =>
{
    options.Address = new Uri(billingGrpcUrl);
})
.ConfigureChannel(options =>
{
    options.HttpHandler = new SocketsHttpHandler
    {
        PooledConnectionIdleTimeout = Timeout.InfiniteTimeSpan,
        KeepAlivePingDelay = TimeSpan.FromSeconds(60),
        KeepAlivePingTimeout = TimeSpan.FromSeconds(30),
    };
})
.AddInterceptor(() => new GrpcDeadlineInterceptor(grpcCallDeadline))
.AddInterceptor(() => new ServiceAuthClientInterceptor(billingS2sCaller, billingS2sToken))
// ↓ ДОБАВИТЬ ЭТУ СТРОКУ:
.AddResilienceHandler("billing-usage", pipeline =>
{
    pipeline
        .AddRetry(new HttpRetryStrategyOptions
        {
            MaxRetryAttempts = 3,
            Delay = TimeSpan.FromSeconds(1),
            BackoffType = DelayBackoffType.Exponential,
            ShouldHandle = new PredicateBuilder<HttpResponseMessage>()
                .Handle<RpcException>()
                .Handle<HttpRequestException>(),
            Name = "billing-retry"
        })
        .AddCircuitBreaker(new HttpCircuitBreakerStrategyOptions
        {
            SamplingDuration = TimeSpan.FromSeconds(30),
            FailureRatio = 0.5,
            MinimumThroughput = 10,
            BreakDuration = TimeSpan.FromSeconds(15),
            Name = "billing-circuit-breaker"
        });
});
services.AddScoped<IBillingProvider, GrpcBillingProvider>();
```

**Ключевые решения:**
- `AddResilienceHandler` — extension на `IHttpClientBuilder`, цепляется прямо после `AddGrpcClient`
- `MaxRetryAttempts = 3` + exponential backoff (1s → 2s → 4s) — покрывает кратковременные сбои
- `CircuitBreaker`: после 50% ошибок из 10+ вызовов за 30с — разрыв цепи на 15с
- Обрабатываем `RpcException` (gRPC) + `HttpRequestException` (сеть)
- **Не retry'им 4xx** — только транзиентные ошибки
- `RecordUsageAsync` идемпотентен по `request_id` — повторные вызовы безопасны

## Что НЕ меняется

- `ChatCompletionHandler.RecordUsageFireAndForget` — паттерн `_ = ... .ContinueWith(...)` остаётся
- `GrpcBillingProvider.RecordUsageAsync` — метод не меняется, retry автоматически через resilience pipeline
- `BillingApplicationService.RecordUsageAsync` — серверная логика не затронута
- Нет новых таблиц, миграций, worker'ов

## Что покрывается

| Сценарий | Поведение |
|----------|-----------|
| BillingService временно недоступен (<30с) | 3 retry → success |
| BillingService долго внизе (>30с) | Circuit breaker открывается, fail fast 15с, потом retry |
| Сетевая ошибка (DNS, timeout) | Retry с backoff |
| BillingService вернул ошибку | Retry если 5xx, не retry если 4xx |
| ApiGateway рестарт | Событие потеряно (accepted trade-off) |

## Rollback

Удалить `AddResiliencePipeline` из `ApiGatewayExtensions.cs` — всё вернётся к текущему fire-and-forget без retry.
