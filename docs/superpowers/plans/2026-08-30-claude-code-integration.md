# Подключение Claude Code к OpenRussiaRouter

## Решение

**Да: для прямого подключения Claude Code нужен Anthropic-совместимый вход. Но реализовывать весь Anthropic API и собственный конвертер не нужно.**

Достаточно добавить `POST /v1/messages` в ApiGateway, а преобразование запросов и ответов поручить существующему F9Router. Claude Code через `ANTHROPIC_BASE_URL` использует Messages API, а не OpenAI Chat Completions. [Контракт Claude Code](https://code.claude.com/docs/en/llm-gateway-protocol)

Пользователь передаёт **существующий публичный Model ID**, как сейчас в OpenAI API. Дополнительных псевдонимов и отдельного каталога не создаём.

Поток: Claude Code → ApiGateway с авторизацией и биллингом → F9Router → выбранная модель.

## Изменения

### 1. Anthropic-вход в ApiGateway

- Добавить `/v1/messages` для обычных и streaming-запросов, включая запросы с `?beta=true`.
- Создать отдельный Messages-handler и методы проксирования с суффиксом `Async`; не направлять Anthropic-тело в существующий Chat Completions-handler.
- Использовать текущие проверки API-ключа, баланса, spend-лимитов, доступности модели и выбор ноды.
- Сохранить текущий маппинг `Model ID → RouterModelId`. Не ограничивать модели семейством Claude.
- Поддержать `Authorization: Bearer` и `x-api-key`. Авторизация и rate limiting должны использовать один выбранный ключ; разные значения в двух заголовках отклонять.
- Передавать в F9Router пользовательский `sk-or-*`, никогда не control token.

Точка регистрации — [ApiGatewayExtensions.cs](../../../src/OpenRussiaRouter.ApiGateway/Application/Extensions/ApiGatewayExtensions.cs).

### 2. Сохранение протокола

- Передавать `anthropic-*` заголовки, `system`, блоки сообщений, инструменты, `cache_control` и неизвестные поля без потерь.
- Менять модель и нормализовать параметры reasoning по текущим разрешённым уровням из Billing. Для Anthropic использовать `output_config.effort`; неверный уровень заменять дефолтом, неподдерживаемое управление reasoning удалять. Числовой thinking-budget не должен обходить ограничения каталога.
- Не добавлять OpenAI-поле `stream_options` и не преобразовывать блоки сообщений в строки.
- Реализовать отдельную SSE-сессию: сохранять `event:`, `data:`, комментарии, ping и границы событий; передавать данные сразу, без накопления полного ответа.
- Повторять запрос на другой ноде только при сетевых ошибках/5xx до начала ответа клиенту. Ошибки 4xx не повторять. Лизу освобождать и при отключении клиента.
- Собственные ошибки выдавать в Anthropic-envelope. Корректные upstream-ошибки сохранять, включая сообщение; после начала SSE не дописывать JSON-ответ.

Текущий [RouterStreamSession.cs](../../../src/OpenRussiaRouter.ApiGateway/Router/RouterStreamSession.cs) напрямую не подходит: он отбрасывает именованные SSE-события.

### 3. Usage и точечная правка F9Router

- Исправить streaming-нормализацию F9Router: свёртку кэша в OpenAI-формат применять только для соответствующего клиентского формата.
- Для Messages добавить в `_orr_raw` однозначные необуферизованные Anthropic-счётчики: вход, выход, чтение и запись кэша. Старый OpenAI-контракт сохранить.
- В ApiGateway объединять usage из `message_start.message.usage` и `message_delta.usage`. Накопительные значения заменять, а не суммировать повторно. [Семантика Anthropic streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)
- Предпочитать `_orr_raw`, чтобы не тарифицировать служебный запас 9Router в 2000 токенов.
- Сохранить тарифную модель ORR: общий вход включает обычный ввод, чтение и запись кэша; `CacheTokens` содержит только чтение. Запись кэша оплачивается как обычный ввод.
- Использовать существующий usage-outbox и идемпотентность. Отсутствующий usage отмечать `usage_missing`; не придумывать токены.

## Подключение клиента и документация

После выпуска пользователь задаёт:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.rawrter.com",
    "ANTHROPIC_AUTH_TOKEN": "sk-or-ВАШ-КЛЮЧ",
    "ANTHROPIC_MODEL": "СУЩЕСТВУЮЩИЙ_MODEL_ID"
  }
}
```

**Base URL — без `/v1`.** Ключ хранится в пользовательской конфигурации или окружении, не в репозитории. [Настройка подключения](https://code.claude.com/docs/en/llm-gateway-connect)

- Выбор другой модели — `/model <Model ID>` или параметр `--model`.
- Задокументировать привязку клиентских `ANTHROPIC_DEFAULT_*_MODEL` к существующим ID, чтобы фоновые запросы не использовали отсутствующие модели.
- Исправить русскую и английскую инструкции интеграции; разделить OpenCode и Claude Code.
- Обновить архитектурные инструкции ApiGateway и описание контракта F9Router.

## Проверки и выпуск

- Контрактные тесты: JSON, SSE, `?beta=true`, оба способа авторизации, лимиты, неизвестная/отключённая модель.
- Streaming: текст, несколько tool calls, `tool_result`, thinking, ping, фрагментированный JSON, ошибка и отключение клиента.
- Billing: обычный ввод, cache read/write одновременно, `_orr_raw`, отсутствие usage, отсутствие повторного списания.
- Проверить настоящий цикл Claude Code: прочитать файл → вызвать инструмент → обработать результат → продолжить диалог.
- Проверить Claude и доступных представителей других транспортов: OpenAI, Gemini, GLM/Kimi. Новый Model ID должен работать без изменения gateway.
- Выполнить сборку и тесты:

```powershell
rtk dotnet build OpenRussiaRouter.sln --no-restore -nr:false -m:1
rtk dotnet test OpenRussiaRouter.sln --no-build -nr:false -m:1
```

Выпускать сначала совместимый F9Router, затем ApiGateway; документацию публиковать после smoke-тестов. Проверить сохранность OpenAI API и отсутствие буферизации на публичном HTTPS-входе.

## Границы первой версии

- `/v1/messages/count_tokens` отложить: он необязателен, Claude Code имеет fallback; текущая реализация F9Router — приблизительный подсчёт по символам.
- Существующий `/v1/models` не менять; автоматическое заполнение меню Claude Code не требуется.
- Все опубликованные Model ID доступны для маршрутизации, но Messages не добавляет модели отсутствующие способности. Медиа-only модели не становятся чат-моделями, а качество инструментов зависит от выбранной модели.
- Совместимость не-Claude моделей обеспечивается нашим шлюзом и F9Router; Anthropic официально такой сценарий не поддерживает. [Ограничение поддержки](https://code.claude.com/docs/en/llm-gateway)
