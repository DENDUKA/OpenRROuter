# Выравнивание Model ID с Combo Router Model

## Цель

Для каждой карточки каталога `Model ID` должен в точности совпадать с
`Router Model`. Целевые Combo-алиасы остаются главным проверяемым набором.

## Границы

- Изменяются только значения `model_id` в строках `billing.model_prices`.
- Сохраняются цены, описания, модальности, доступность, приоритеты и провайдеры.
- Исторические таблицы использования и бухгалтерские записи не переписываются:
  они остаются неизменяемым аудитом уже обработанных запросов.
- Отдельная карточка `GLM-5.2`, которую пользователь исключил из списка,
  не требует изменения, поскольку её значения уже совпадают.

## Подход

Транзакции PostgreSQL сначала проверяют отсутствие коллизий, затем меняют
`model_id` у 16 Combo-карточек и трёх ранее существовавших карточек вне этого
набора. Карточки с уже совпадающими значениями не изменяются. Изменение
первичного ключа безопасно: в схеме нет внешних ключей на
`billing.model_prices.model_id`.

## Проверка

После транзакций запрос по всему каталогу должен вернуть ноль несовпадений.
Отдельный запрос по 18 целевым Combo должен подтвердить для каждой
карточки: `model_id = router_model_id`, ровно одну карточку, включённый статус,
заданные цены, описания на русском и английском, а также входные и выходные
модальности.
