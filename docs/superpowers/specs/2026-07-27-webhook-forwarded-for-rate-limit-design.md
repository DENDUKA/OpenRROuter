# T-006: защита rate-limit платежных вебхуков от подмены X-Forwarded-For

## Цель

Не позволять внешнему клиенту обходить per-IP rate limit платежных вебхуков, подставляя новые значения `X-Forwarded-For`.

## Решение

В `WebApp/Program.cs` оставить `UseForwardedHeaders` первым middleware и добавить `ForwardLimit = 1` в `ForwardedHeadersOptions`. Приложение будет доверять только ближайшему proxy hop, добавленному Caddy, и использовать его фактический клиентский IP для `HttpContext.Connection.RemoteIpAddress`.

Списки `KnownNetworks` и `KnownProxies` не привязывать к диапазону Docker: сеть развёртывания может меняться. Изменение не затрагивает обработку `X-Forwarded-Proto` и `X-Forwarded-Host`, поэтому OAuth redirect URL и абсолютные ссылки сохраняют существующее поведение.

## Проверка

Добавить интеграционный тест на endpoint вебхука. Он должен отправлять запросы через модель цепочки `X-Forwarded-For`, где изменяется только клиентская часть, а ближайший proxy адрес остаётся одним и тем же. После 60 запросов следующий должен получить HTTP 429. Это докажет, что смена подставленной клиентской части не создаёт независимые rate-limit bucket’ы.

## Вне области

Не менять лимит 60 запросов в минуту, правила подписи вебхуков, конфигурацию Caddy и общие правила trust boundary для иных сервисов.
