## Prompt

Добавить фоновую очистку `usageHistory` в локальной SQLite БД 9Router: удалять записи старше настроенного окна батчами, не блокировать event loop одним большим DELETE, и запускать `incremental_vacuum` только когда БД уже переведена в `auto_vacuum = INCREMENTAL`.

- `src/OpenRussiaRouter.9Router/src/lib/db/repos/usageRepoRetention.js` (создать)
- `src/OpenRussiaRouter.9Router/src/shared/services/initializeApp.js` (изменить)
- `src/OpenRussiaRouter.9Router/.env.example` (изменить)

## Что нужно сделать

### 1. Включить incremental auto-vacuum для свежих БД

В `PRAGMA_SQL` добавить:

```sql
PRAGMA auto_vacuum = INCREMENTAL;
```

Это должно применяться к новым пустым БД. Для существующих БД это не заменяет maintenance из `OR-003`.
Для существующих БД это безопасный no-op до выполнения full `VACUUM`: не пытаться запускать `VACUUM` в этой задаче.

Inline-правку пометить `ORR-PATCH`.

### 2. Создать `usageRepoRetention.js`

Новый модуль должен экспортировать функцию запуска, например:

```js
export function startUsageHistoryRetentionJob()
```

Функция должна:

- быть idempotent внутри процесса через `globalThis`, чтобы Next.js HMR / повторный init не создавал несколько таймеров;
- читать конфиг по схеме `raw?.field ?? env ?? default`, не через `getSettings()` с подмешанными дефолтами;
- поддерживать настройки:
  - `usageHistoryRetentionDays` / `USAGE_HISTORY_RETENTION_DAYS`, default `30`;
  - `usageHistoryRetentionIntervalMs` / `USAGE_HISTORY_RETENTION_INTERVAL_MS`, default `3600000`;
  - `usageHistoryRetentionBatchSize` / `USAGE_HISTORY_RETENTION_BATCH_SIZE`, default `10000`.

### 3. Реализовать батчевый DELETE

Каждый tick должен удалять старые строки циклами:

```sql
DELETE FROM usageHistory
WHERE id IN (
  SELECT id FROM usageHistory
  WHERE timestamp < ?
  LIMIT ?
)
```

Требования:

- cutoff считать в JS через `new Date(Date.now() - days * 86400000).toISOString()`;
- после каждого batch делать `await new Promise(resolve => setImmediate(resolve))`;
- завершать цикл, когда `changes === 0`;
- не удалять `usageDaily`.

### 4. Условно запускать `incremental_vacuum`

После DELETE проверить:

```sql
PRAGMA auto_vacuum;
```

SQLite возвращает числовой режим:

- `0` = `NONE`
- `1` = `FULL`
- `2` = `INCREMENTAL`

Проверять нужно именно значение `2` (например, `row.auto_vacuum === 2` с учётом формы результата конкретного adapter'а).

Если режим `INCREMENTAL`, выполнить:

```sql
PRAGMA incremental_vacuum(1000);
```

`1000` страниц — ограниченный порционный reclaim, примерно до 4 МБ при page size 4 КБ. Full `VACUUM` и попытка освободить весь freelist одним фоновым вызовом в эту задачу не входят.

Если режим не `INCREMENTAL`, не делать full `VACUUM`, а только залогировать skip:

```text
[usageRetention] deleted={N} vacuumed=0 mode=skip reason=auto_vacuum_disabled
```

Для драйвера `sql.js` отключить VACUUM-часть независимо от режима и залогировать conservative mode. Точное значение драйвера в текущем adapter'е — `adapter.driver === "sql.js"`. Целевой production-драйвер для полного поведения — `better-sqlite3`.

### 5. Подключить job в init-хук

В `initializeApp.js` запустить retention job один раз при старте приложения.

Ошибки job'а не должны валить приложение. Они должны логироваться с префиксом `[usageRetention]`.

### 6. Обновить `.env.example`

Добавить:

```env
USAGE_HISTORY_RETENTION_DAYS=30
USAGE_HISTORY_RETENTION_INTERVAL_MS=3600000
USAGE_HISTORY_RETENTION_BATCH_SIZE=10000
```

## Что НЕ менять

- Не добавлять `usageHistoryEnabled`.
- Не удалять и не менять `usageDaily`.
- Не запускать full `VACUUM` из фонового job'а.
- Не менять API маршрутов usage dashboard.
- Не менять BillingService / Gateway.

## Критерии готовности

- На `better-sqlite3` job удаляет строки старше retention window батчами.
- Между batch-итерациями есть yield через `setImmediate`.
- При `auto_vacuum != INCREMENTAL` job не запускает full `VACUUM` и логирует skip.
- При `adapter.driver === "sql.js"` VACUUM-часть отключена, DELETE остаётся best-effort.
- Повторный вызов `initializeApp()` не создаёт второй retention timer.
- `.env.example` содержит все три retention-переменные.
- Сборка 9Router проходит стандартной командой проекта или в отчёте указана причина, почему она не запускалась.
